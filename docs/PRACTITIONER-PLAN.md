# 风水师工作台 —— 让 HideFate 从「算得准」走到「用得上」

> 设计决策记录。与 [README](../README.md) 硬规则、[ROADMAP](ROADMAP.md) 有出入之处，均在 §9 列明，不做静默变更。
> 起草：2026-10-16。

---

## 0. 一句话结论

引擎已经够严谨（三派合参、账本、对轨、可证伪占局），**缺的是风水师上门那一整套工作流**：
起盘要快、勘察要顺、断事要先断后问、结论要落成「做什么／在哪／何时／谁」、报告要能直接交给客户、流年要能追着复查。

**定位调整**：主用户从「普通用户自己看」改为 **风水师（practitioner）为客户做案**。
普通用户仍可用，但界面、数据结构、报告都以风水师接案的流程为骨架。

---

## 1. 三个痛点 → 三条设计对策

| 痛点（kt 原话） | 根因 | 对策 |
|---|---|---|
| **结果不是行动** | 输出是「某人某月健康偏高 12%→18%」，风水师拿去没法跟客户说、客户没法做 | 一切结论最终落成 **行动卡**（§2），按优先级排，标在户型图上，带日期 |
| **输入太多才有结果** | 建档向导先要房、人、房间映射，才出任何东西 | **十秒起盘**：坐向度数 + 年份即出全盘；其余渐进补；现场用手机罗盘与户型图叠宫取代手填 |
| **不信任输出** | 概率权重是工程取值；门派选择被写死；看不到推导 | 门派设置交给风水师；每条结论可展开推导链；**师断可覆盖引擎断**并分别入账；对外不出百分比 |

## 2. 核心新类型：行动卡 `Action`

> **第零期修订（2026-10-16，采纳外部审阅）**：下方草案里的 `priority: 必做/宜做/可选` 与
> 「层级优先」排序已作废。现行定义见 `packages/core-synthesis/src/action.ts`：
> `category`（安全须知／本派建议／可选传统做法）、`evidence`（完整／初步）、`reversibility`、
> `needsOwnerApproval`、`approval`（待审）；排序为 **类别 → 依据 → 可逆性 → 成本 → 人数**，
> 传统层级 `tier` 只作参考字段。互相矛盾的行动不进客户清单，改列「待裁量」。

所有模块（勘察、验宅、流年、择日、看房、摆放）的终点都是它。没有对应行动的结论，只进「专业视图」，不进客户报告。

```ts
export interface Action {
  readonly id: string;
  /** 动词开头的一句话：「把主卧床移到东墙」「北方今年勿动土」。 */
  readonly title: string;
  /** 化解层级，排序第一依据：能改格局就不靠摆件（《宅经》移形易位之义）。 */
  readonly tier: '移形易位' | '改房间用途' | '调整动线门窗' | '择时避让' | '物件化解' | '留意观察';
  /** 落点：宫位 + 可选的户型图坐标（户型图叠宫完成后才有）。 */
  readonly where: { palace: Palace; room?: string; planXY?: [number, number] };
  /** 何时做 / 何时撤：流年行动必须有起止，如「2027-02-04 立春前完成，2028 立春后撤」。 */
  readonly when?: { doBy?: string; undoAfter?: string; recurring?: '每年立春' | '每月交节' };
  /** 主要针对谁（按人算，承接 README 规则 7）。 */
  readonly forMembers: readonly string[];
  readonly priority: '必做' | '宜做' | '可选';
  /** 为什么：指回 Finding（门派、置信度、古法依据三必填不变）。 */
  readonly because: readonly FindingRef[];
  /** 客户成本感受，不是金额。 */
  readonly effort: '不花钱' | '小改' | '装修级';
  /** 若受条件所限做不了，次选方案。 */
  readonly fallback?: string;
  /** 来源：引擎生成，还是风水师新增/改写。 */
  readonly author: '引擎' | '师断';
}
```

**排序规则**：`priority` → `tier`（移形易位最先）→ 受影响人数 → `effort`（同效取省事）。
客户报告第一页就是这张清单，不是九宫盘。

## 3. 风水师的工作流（新的产品骨架）

```
案件 Case ─┬─ 客户与家人（八字精度分级照旧）
           ├─ 场所 Site × N（住家 / 办公 / 店铺 / 候选房源）
           │     └─ 勘察 Visit × N（日期、罗盘读数、照片、户型图、形煞清单）
           ├─ 断事验宅（先断后问，§5）
           ├─ 行动清单（Action，含完成勾选）
           ├─ 报告（交付版本留档）
           └─ 流年复查（每年立春前自动生成新清单）
```

**底部导航建议**（导航顺序即工作顺序）：`案件 · 勘察 · 断事 · 日历 · 我的`。
一生／紫微／占局降为案件内的「命层参考」与二级工具 —— 对风水师，命层的作用是给出**命卦、用神／忌神**去筛宫位，不是日常入口。

> schema 层：在已做的「人为中心」之上加 `Client → Case → Site → Visit` 一层。越早做越省（同 overview 里「schema 倒置」的判断）。

## 4. 模块与优先级

### P0 · 地基（先做，否则后面全返工）

1. **案件 schema**（§3）+ 导出/导入整案 `.hidefate.json`（手机现场采集、电脑出报告，本地优先不变）。
2. **门派设置**（风水师档案级，可逐案覆盖，**印在报告页脚**）：
   - 运盘取 **建成年 / 入住年 / 大装修换天心**（三选一，默认入住年；二手房提示换天心选项）
   - 五入中借宫规则（现有 `CenterFiveRule`）
   - 替卦阈值（默认兼 3°，可设 2°–4.5°）
   - 分宫法：**九宫井字** vs **八卦 45° 放射** vs **二十四山 15° 放射**
   - 公寓/组屋立向：**单元大门 / 阳台主窗（纳气口）/ 大楼大门** —— 各派不同，必须让师选
   - 楼层五行（河图数）：默认**关闭**，标「待考」
   - 罗盘基准：**磁北（默认，与传统罗盘一致）** / 真北
3. **十秒起盘**：只填坐向度数 + 年份 → 立即出运盘、山向盘、流年、八宅游年、替卦/兼向提示。房间、家人、户型图都是之后的「补充」，补一样多一层结论，**不补也不挡路**。
4. **行动卡**落地，现有 `advice.ts` / `cures` / `roomPlan` 的输出统一改为产出 `Action[]`。

### P1 · 现场勘察（解决「输入太多」的大头）

5. **手机罗盘**
   - iOS：`DeviceOrientationEvent.requestPermission()`（需用户点击触发）+ `webkitCompassHeading`
   - Android：`deviceorientationabsolute`，heading = 360 − alpha（手机平放）
   - 流程：屋内 **三处各读一次** → 剔除离群 → 显示读数与 **误差带**（手机典型 ±5°，近钢筋/电器更差）
   - 误差带若跨 **山界（每山 15°）或替卦区** → 红字：「兼向／替卦风险，请以罗盘复核」，并把两种盘都排出来让师选
   - 手填度数保留，作为罗盘复核后的覆盖值
6. **户型图叠宫**
   - 拍照 / 上传 → 拖四角校正 → 描外轮廓（多边形）
   - 太极点：多边形 **几何重心**；缺角/凸出按「不足一边三分之一为缺」自动判，师可改
   - 按 P0 选的分宫法叠线，点房间贴标签（主卧、厨房、大门、厕所、神位、收银台……）
   - 之后所有行动卡都能**直接标在这张图上**
7. **亚洲物业类型**（现有 15 类基础上补齐，各带默认立向规则与勘察清单）：
   - 住宅：店屋楼上住家、唐楼、村屋、复式/跃层/顶层复式、SOHO/服务式公寓、联排别墅（cluster/townhouse）
   - 商业：**店屋（Shophouse）**——楼下店以店门立向、楼上住家单独论或同向论（师选）、诊所/中心类（补习、美容、医疗）、写字楼整层
   - 复式规则：各层共用坐向，各层**各自求太极点**，楼梯位置单列体检
   - 每类的 `weights`（现为工程取值）改为「门派预设」可被师调，调过的值随案存档
8. **形煞拍照清单**：路冲、反弓、天斩、壁刀、开口、尖角、高压电塔、对面庙宇/医院/殡仪……每项可附照片、方位（取当时罗盘读数），自动并入峦头评分与行动卡。

### P1 · 断事验宅（kt 新提的需求，见 §5 详述）

9. **以事验宅**：把「入住以来发生了什么」与这间屋的盘对上，并推出「同一机制下次何时再来」。

### P2 · 时间维度

10. **流年 / 流月行动清单 + 日历导出**
    - 每个场所在**立春前**自动生成新一年清单，每月**交节前**生成月清单
    - 例（2027 丁未）：立春 2027-02-04 起，**五黄到北、二黑到西**；太岁在未（西南偏南）、岁破在丑（东北）、三煞在西 —— 西、东北、西南偏南勿动土；北方若是大门/主卧，须在立春前完成化解
    - **导出 `.ics`** 给客户：风水师把提醒直接送进客户手机日历，不依赖 PWA 推播（iOS 推播需安装且需服务器）
11. **择日**（入宅、动土、安床、开业、签约、装修开工）
    - 数据源：`lunar-typescript` 已有日宜忌、冲煞、十二建除、黄黑道、吉神凶煞 —— 现成可用
    - 本项目只加三件事：**① 硬性排除**（岁破、月破，及师设的四离四绝等）；**② 逐个家人生肖排日冲**、动土另查当年三煞/太岁方是否正是施工方位；**③ 排序 + 说明**（列 2–3 个吉日，每个写清吉神组合与为何排除邻近日子）
    - 入宅附「宜从何方入门」（主事者命卦吉方）
    - 须核对 `lunar-typescript` 宜忌表与《协纪辨方书》之出入，有出入处标注，**不静默取一边**（同紫微立春年界的处理）

### P3 · 交付

12. **看房比较**（kt 自己买房也用得上）
    - 2–3 套候选并排：**可买 / 慎 / 不买**
    - **红线**（任一触发即「慎」或「不买」，师可调）：九运盘主事者宫或大门处于长期凶组合且无法移位；上山下水而外局无法补救；主事者宫大缺角；不可化解的外煞（反弓、正对路冲且无遮挡空间）
    - 每个问题标 **可改 / 不可改**（可改：房间用途、床位、换门；不可改：坐向、缺角、外局）—— 这是买家真正要的信息
    - 每位家人适配度（命卦东西四命 × 宅卦、用神方位能否安排到该人卧房）
13. **摆放图**：床（床头靠实墙、避梁/镜/厕墙、头向按命卦四吉）、书桌/老板位（背有靠、见门不对门）、炉灶（坐凶向吉）、收银台/财位（九运向星九、一、八）、神位、水（九运零正神）→ 全部画在户型图上，受限时给次选。
14. **报告**：风水师品牌（名号、印章图、联系方式）、**中/英双语**（马新客户常需）、师断可编辑、行动清单置首页、附流年 `.ics`、一键导出 PDF 发 WhatsApp。门派设置印页脚。

## 5. 断事验宅 —— 详细设计

### 5.1 目的

客户问「我们搬进来后老公事业一直卡、婆婆身体差，跟这屋有关吗？以后呢？」。
风水师要的是：**哪些事对得上这屋的哪一宫哪一组星、对不上的老实说对不上、对得上的机制下一次在哪年哪月再被引动。**

### 5.2 顺序：先断后问（不可颠倒，承接 ROADMAP §5）

```
1. 起盘 + 户型 + 家人分房完成
2. 引擎生成「此宅入住以来最可能已发生之事」5–8 条
   每条：哪一宫 / 哪个房间 / 谁 / 哪几年最重 / 依据 → 冻结入账、盖时间戳
3. 风水师当面逐条问客户：中 / 部分中 / 未发生 / 相反 ；可补「该期此域无事」（负样本）
4. 再录入客户主动说的其他事（年/月、谁、哪方面）
5. 引擎对每件事给归因候选：
     - 风水层：宫位星组合 × 流年/流月引动 × 当事人卧房/常待之处
     - 断点：事情是否卡在搬家年、装修年（搬家＝自然实验，沿用 breakpoints.ts）
     - 命层：是否卡在大运交界、流年冲克（有八字才出）
     - 都对不上 →「本屋盘面无对应，可能与命运层或非风水因素有关」
6. 向前推：同一机制下次引动的年 / 月 → 生成带日期的行动卡
```

**为什么这对风水师最实用**：上门「断中三件事」就是建立信任的方式；而且由于第 2 步先锁，系统与师本人都不能事后改口，**准不准一目了然**——这直接回答「不信任输出」。

### 5.3 宅级断事模板（新数据，接到 `core-events`）

在现有 53 组双星组合之上，补宅级、带房间语境的模板，例如：

| 组合 / 情境 | 房间语境 | 断事方向 | 引动 |
|---|---|---|---|
| 二五同宫 | 主卧 / 长者房 | 健康留意（不写病名，§9） | 流年二或五再临 |
| 三七（穿心） | 大门 / 客厅 | 盗损、口舌官非 | 流年三、七临 |
| 六七（交剑） | 主卧 / 办公 | 争执、冲突 | 流年六、七临；金年加重 |
| 二三（斗牛） | 大门 / 主卧 | 口舌是非、关系紧张 | 流年二、三临 |
| 一四 / 四一 | 书房 / 学生房 | 读书、考试、文书利 | 流年一、四临 |
| 八九 / 九八 | 大门 / 主卧 | 喜庆、置产、添丁 | 流年八、九临 |

- 每条仍走 `minResonance`、`interventionability`；病名禁入 schema（principles 已定）
- 模板须分「正典 / 待考」两档，**待考档默认不进客户报告**（同双星断事的 canonical 分档）

## 6. 信任：怎么让风水师敢用

1. **推导链可展开**：任何一条结论点开即见 运盘 → 山向星 → 组合 → 流年 → 房间/人 → 古籍出处。
2. **门派显式**：§4-2 的设置写进每份报告页脚；改设置即重算并标「本案门派与默认不同」。
3. **师断覆盖**：风水师可改写、删、加结论与行动卡；`author: '师断'` 与引擎断**分开入账** —— 一年后可以看「引擎对、我对、都对、都错」各几条，这是风水师自己的校准，也是产品最强的说服力。
4. **案例库**：结案后（客户回报）进入风水师个人案例库，按组合/房间/物业类型检索「我以前遇过的同类局」。
5. **对拍扩充**：九运二十四山下卦全表 + 替卦全表对公开盘式做回归；新增「门派开关 × 盘式」组合测试。
6. **对外不出百分比**：客户报告只用档位（明显偏高 / 偏高 / 平常 / 偏低）与行动；百分比、`breakdown` 留在专业视图。
7. **删掉削弱可信度的内容**：数字玄机下架（已评估为不可证伪）；面相按既定「自我观察提示」重构，不进风水师报告。

## 7. 不做什么（刻意）

- 不内置「转运物品商店」或推荐购买特定摆件（不说「必须摆 XX」）
- 不把元运换运当归因证据（沿用 breakpoints 规则）
- 不在客户版给决定论措辞（3%–92% 收敛与「不说必定」保留）
- 不为普通用户另做一套简化 App；简明/专业是同一 App 的两个视图

## 9. 与现有硬规则的关系

| 规则 | 变化 |
|---|---|
| 1 LLM 不发明数字 | 不变。师断是人写的，不是模型写的，且单独标作者 |
| 2 结论三必填 | 不变；行动卡的 `because` 必须指回 Finding |
| 3 概率 3%–92% | 不变；只是客户视图不显示数字 |
| 4 无化解不出预测 | 按 ROADMAP P5 修订方向走：出预测但标可干预性；客户报告只列有行动的 |
| 6 三条建档路径能力相同 | 加强：十秒起盘是第四条、最轻的路径，能力仍相同、只差置信度 |
| 7 按人算 | 不变；行动卡 `forMembers` 承接 |
| 新增 | **门派选择必须显式且印在报告上**；**师断与引擎断分开入账**；**断事先锁后问** |

## 12. 更多建议（按实用价值排）

1. **客户预填问卷**：风水师上门前发一个链接（或二维码），客户自己填生辰、入住年、户型照片、「入住以来发生过什么」。生成整案文件，现场一键导入。这是解决「输入太多」最省力的一招 —— 输入的人从风水师变成客户，且是在上门前。
2. **化解物品台账**：每件摆件记「摆在哪、哪天摆、何时撤」，撤除日直接来自行动卡的 `undoAfter`。立春前自动列出「该撤的、该换位的」—— 这是年度复查的核心，也是风水师的回头生意。
3. **城门诀、七星打劫**：第一期格局体检的自然下一步。两者门派分歧较大，须先由 kt 定一套表（或提供你信的书页），再做全量对拍，不凭记忆实现。
4. **卫星图 + 二十四山叠层**：远程看盘时，在地图上叠罗盘线，标路冲、反弓、水口、高楼（都市「高楼即山、道路即水」）。能顺便由建筑轮廓估坐向，作罗盘读数的第二来源。
5. **案件状态与回访**：预约 → 勘察 → 交报告 → 三个月回访 → 年度复查。回访收「做了哪些、效果如何」，直接进账本（现有 `AppliedCure.effectiveness`），一年后可看哪类化解真有用。
6. **办公与店铺专用**：老板位（背有靠、坐生气／延年、面向当旺向星）、员工按命卦排座、收银台与保险箱落向星九一八、开业择日。现有 `BUILDING_PROFILES` 已有骨架，缺的是「排座」这个动作。
7. **九运购房速查表**（看房模式的雏形，见附表）：九运下卦二十四山中，没有旺山旺向与上山下水，全是双星会向／会坐；坎离一线（壬子癸、丙午丁）六山带伏吟或反吟；甲卯乙、辰巽巳、乾亥向等带合十或未来入囚。买家看房时这张表就能先筛掉一批。

## 13. 第一期顺带发现的引擎问题（未改，待 kt 定）

1. **星曜旺衰一直以宅之元运论。** 八运宅在 2026 年，引擎仍把八白当「当旺」、九紫当「生气」。很多玄空门派以**时运**（当年所在元运）论旺衰。改默认会改动所有八运宅的分数，所以第一期只加了开关（`phaseBasis`，默认「宅运」）。**建议 kt 定一个默认。**
2. **同宫化解互相打架。** 例：八运巽山乾向，正西五黄七赤同宫 —— 五黄条「忌深色鱼缸」，七赤条「宜深色鱼缸泄金」。原因是化解按单星各出一条。第一期只做了「标出矛盾」；根治要改成按**组合**出化解（starMeta 的组合表已有 53 组，可在其上补组合级化解）。
3. **化解文字层仍有健康字眼**：「有慢性病者」「神经系统病史」「定期检查血压与心血管」等出现在化解建议里。与 principles 里「病名须在 schema 层排除」一条冲突，建议下一期清理为「健康留意」类措辞。
4. 化解的「立即／本年内／从容」三档，与流年星引起的化解没有区分开；第一期以「今年」开头识别流年化解并加撤除日期，长远应在 `Cure` 上加显式字段。
